# 上海大师赛 · 决赛日攻略雷达

用户 2026-10-18（周日）**只去决赛当天、自己开车去**。他要的是"到了现场怎么顺"，按他 2026-10-11 明确的口径排序：

**① 开车停哪条路最近、导航到哪 → ② 能带什么/不能带什么（水杯能不能带）→ ③ 赛况与决赛最可能谁对谁 → ④ 网上（小红书/微博）大家在讨论什么 → ⑤ 天气/吃饭**。

这是个**情报雷达**，不是赛事播报：报"改变你现场行为"的信息，不报战报流水与球星八卦。

## 铁律（违反任何一条 = 这期作废）

1. **只用两个脚本，不手拼搜索命令**：`masters_fetch.py`（抓取，含官方签表/赛果）+ `masters_weather.py`（天气）。原始 JSON 不进聊天，只进你的判断。
2. **交通只报自驾**：用户明确"我不会用公共交通了"。地铁/短驳专线/出租车/返程专线**一律不报**（自驾导航、停车区、散场路线、即停即走点位除外）。
3. **同名赛事必须硬过滤**：「上海大师赛」= 网球 / 斯诺克 / 电竞 / 狼人杀（京城大师赛）。脚本已过滤，**你自己 web_search 的结果要再过一遍**（黑名单见 `references/sources.md`）。疑似混入 → 直接剔除，不留"可能"。
4. **抓不到的渠道不许假装读到**：**小红书笔记正文**、知乎搜索、大众点评正文、微博搜索页 → 本机抓不到（登录墙/反爬，实测）。小红书只能引**标题+摘要**并标「转述」；**微博帖子正文页可以抓**（`www.weibo.com/<uid>/detail/<id>`，实测可读）。
5. **数字必须有出处和年份**：泊位数/价格/班次一律带来源；往年数字写清"（2025 参考）"，**不许写成今年事实**。
6. **一切时间用北京时间**；决赛日写「10/18（周日）」。
7. **赛况只报与"决赛走势"相关的**：谁出局了、还剩哪些种子、决赛最可能谁对谁。**不报每日战报比分流水、不报球星花絮**（除非影响现场：退赛改赛程、开赛时间变动、天气改期）。
8. **报告 ≤28 行、结论前置、分块小标题、大白话**，按 `references/report-template.md` 输出。不写"已按流程生成"之类的元话。

## 数据源：三轨并行

**A 轨 · 脚本**（结构化、可复现，不吃验证码）

```bash
S=~/.hermes/skills/shanghai-masters/scripts
python3 $S/masters_fetch.py all --limit 12        # 官方站正文 + 第三方讨论 + 赛果（cron 用这个）
python3 $S/masters_fetch.py scores                # 只取官方签表+赛果（累积；--days all 可回填）
python3 $S/masters_weather.py --date 2026-10-18   # 决赛日逐时天气（默认就是 10/18）
```

抓取层输出里：
- `official.pages.<页>.relevant` = 官方页里**带实操关键词的段落**（最可靠）
- `social.new_items` = **新增**情报（标题+来源+摘要+链接），已按相关性排序；`source` 含 `微博`／`小红书·转述`／`DDG/<域名>`（媒体稿）
- `social.errors` = 源异常（`百度 安全验证`/`搜狗 验证码`/`ddg: 无结果（疑似限流）`）
- `scores.seeded_alive` = **还在签表里的种子**；`scores.seeded_out` = **已出局种子**（含止步轮次）；`scores.latest_matches` = 最新比赛日单打赛果
- `parking` = OSM 周边停车场（实测数据稀疏，**别当停车方案用**）

**B 轨 · 你自己的 `web_search`**（通用检索主力，不吃 DDG 的限流）

每期 3–5 条针对性查询（模板见 `references/sources.md` §三），例如：
- `上海大师赛 停车 自驾 攻略 元江路`
- `上海大师赛 限带物品 清单 水杯 保温杯`
- `上海大师赛 半决赛 决赛 对阵 预测`

**C 轨 · 脚本内建的 DDG 检索**（媒体稿 / 微博 / 小红书转述，见 A 轨输出的 `social`）
DDG（`html.duckduckgo.com`）**支持 `site:`**，是脚本侧拿到微博帖子、小红书标题摘要的主要入口；但**连续查询会被限流**（返回 202/空结果）→ 脚本已内置 20s 退避重试，并把每期查询压到 4 条（媒体稿 2 + 微博 1 + 小红书 1）。**别在脚本外自己猛刷 DDG**。

⚠️ **DDG 一旦限流，冷却可能长达数小时**（2026-10-11 实测：连续探测后等 20 分钟仍是 202）。此时**不要重试脚本**，改用 B 轨 `web_search` 补讨论热点（模板见 `references/sources.md` §三，含小红书/微博查询）。**本机没有替代搜索引擎可换**：实测 mojeek 超时、brave 429、startpage/sogou/百度/so.com 都不给结果（验证码或 JS 壳）。

**为什么三轨都要**：A 轨拿不到媒体稿（2026 停车警方口径、限带清单全文都在媒体稿里）；B 轨拿不到签表/赛果的结构化数据与微博正文；C 轨受限于 DDG 限流不能多跑。

## 工作流（每期照做）

1. 跑 `masters_fetch.py all --limit 12` + `masters_weather.py`（可并行；`all` 已含 `scores`）。
2. 跑 3–5 条 `web_search`（按 `references/sources.md` §三，按当天轮换维度倾斜）。
3. **筛**：这条值得报吗？判据 = 能不能改变用户 10/18 的现场行为（停哪条路、带不带水杯、几点出门、吃什么）。**战报流水与花絮直接扔**（除非改赛程/开赛时间）。
4. **查**：与 `references/guide-dimensions.md` §二 的已核实事实去重；已告知过的攻略不重复讲（零新增走模板 B）。
5. **写**：按 `references/report-template.md` 输出，≤28 行，来源层标注（官方｜媒体｜微博｜B站｜转述）。
6. 脚本报限流/失败 → 报告末尾一句（单日偶发不报；连续 2 天以上才提）。

## 报告结构（详见 references/report-template.md）

```
🎾 标题行（距 10/18 还有 N 天）
📌 今天最该知道：一句话结论
🅿️ 自驾停车      ← 哪条路最近 / 导航到哪 / 兜底方案 / 散场怎么走
🎒 可带·禁带     ← 直接回答"XX 能不能带"，含清单变化
🏁 赛况走势      ← 已出局种子 / 剩余种子 / 决赛最可能对阵（标推测）
💬 大家在聊什么   ← 微博正文 + 小红书摘要（转述）+ B站，各一句
🌦 决赛日天气    ← 2 行内（≥7 天只算趋势）
————
本期新增 N 条（扫描/保留/去重跳过）+ 源异常（如有）
```

## 阶段策略

| 阶段 | 该侧重 |
|:---|:---|
| 赛前（–10/14） | **积累**：停车方案与导航点位、限带清单逐条确认、往年坑点、餐饮点位、票务规则 |
| 赛期内（已开始） | **现场验证**：去看过的人当天发的实操反馈 —— 停车排队多久、安检快不快、场内餐饮排队、散场好不好走 |
| 临近（10/15 起） | **天气转准**（≥7 天只算趋势，3 天内才可信）+ **出门清单收敛**（几点出门、带什么） |
| 决赛日（10/18） | 决赛日当天版：几点出门/走哪条路 → 停哪 → 入场门与证件 → 散场策略 |
| 赛后（10/19 起） | 任务已到期，不再输出；如被触发，只回"赛事已结束，任务已停" |

## 关键事实（已核实，别重新"发现"一遍）

详见 `references/guide-dimensions.md` §二。要点：**观众自驾停周边六区、统一 10 元/车次含免费 1 小时、2026 共 4020 泊位、由近及远分级开放**；**2 号门在元江路**、是观众唯一入口；**长柄伞/尖头伞、玻璃瓶杯、三脚架、球拍、无人机、>55×40×20cm 行李**都拦；10/17–18 **开门 12:30**；官方接驳时刻表仍挂 2024 版（自驾不用管）；决赛具体开赛时间官方未公布（只写夜场不早于 18:30）。

## Pitfalls

1. **斯诺克/其他同名赛污染**：搜"上海大师赛"约一半结果是斯诺克或狼人杀（京城大师赛）——脚本已过滤，手工 web_search 时必须自己筛。
2. **小红书正文抓不到**（登录墙），**但微博帖子正文抓得到**（`weibo.com/<uid>/detail/<id>` 的 `og:description`）。别再笼统写"微博抓不到"。
3. **DDG 会限流**：连续 5–8 次查询后返回 202/空结果；脚本已退避 20s 重试一次，**但冷却可能长达数小时**（2026-10-11 实测 20 分钟后仍 202）。看到 `ddg: 无结果（疑似限流）` → **用 `web_search` 补媒体稿/微博/小红书**（模板见 `references/sources.md` §三），**不要重试轰炸**（会延长冷却）。本机没有可替代的搜索引擎（mojeek 超时、brave 429、startpage/百度/sogou 无结果）。
4. **`site:` 在 web_search 无效**（Parallel 不支持），要 `site:` 就用脚本里的 DDG。
5. **B站解析**：必须取 `bili-video-card__info--tit` 的 `title` 属性；直接抓 `<a>` 文本会得到播放量"664 0 02:30"。
6. **百度/搜狗会限流**：触发后不要重试轰炸，改走 web_search。
7. **官方赛果页有两个坑**（脚本已处理，改脚本时别踩回去）：① **单打/双打混排**，header 文案完全一样，只能靠块内 name 节点数区分（单打 2 个、双打 4 个）；② **赢下一盘的选手也带 `score-item won`**，胜者判定要用 stats-note 的 `Game Set and Match <全名>.`，兜底才用 won 盘数。
8. **天气窗口**：Open-Meteo 逐日最多 16 天；≥7 天只标趋势，10/15 起才当准数。
9. **OSM 停车场没用**：3km 内全是无名无容量的点，别当停车方案。
10. **往年数字**：350 车位/101 班次/1913 人次/3000 车位都是往年口径，今年用 **4020 泊位（2026-10-05 警方口径）**。
11. **票务站 JS 渲染**：久事体育 APP 页面脚本抓不到，票务靠 web_search 摘要 + 官方英文站 Tickets 页；现场不设售票处。
12. **管道/内联 `python3 -c` 易被审批拦**：探测脚本写成 `~/.hermes/cache/xxx.sh` 再跑。
