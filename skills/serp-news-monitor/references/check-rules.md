# serp_news 巡检口径与边界（详细版）

## 1. 连接与权限
- 地址 `nj-cynosdbmysql-grp-eqjy6v0z.sql.tencentcdb.com`，端口 **25048**，库 `serp_news`，只读账号 `chaxun`。
- 口令只存在于 `~/.hermes/secrets/serp_news_db.env`（chmod 600）；脚本读取顺序：环境变量 `SERP_NEWS_DB_*` > 该文件 > `~/.hermes/.env`。**任何报告、命令行、飞书消息里都不出现口令。**
- 若用户提供新地址/端口，以用户为准；**不得**根据某台应用服务器 IP 自行推测数据库地址。
- 不索要项目 `.env`、SSH 私钥、写库账号。
- 连接超时 10s、读取超时 30s（`config.json` 可调）；只执行 SELECT（脚本对语句前缀做白名单校验）。
- 字段首次确认后可长期复用；字段报错时再核实，不反复猜测。

## 2. 时间与口径
- 时区统一 `Asia/Shanghai`；业务日期 D 默认北京时间昨天，可 `--date` 指定。
- 统计一律按 `fetchdate`。
- 主流水线通常每天 00:30 处理前一天新闻；建议巡检排在 08:00（最终以用户 cron 设置为准，本 skill 不建 cron）。
- `score` 取值 0–5；**NULL = 未评分**，0 分可能来自空正文或规则处理。
- 「高分」= `score>=4`；「普通摘要处理门槛」= `score>=3`（两者不是一回事）。
- 正文 ≤500 字时，把原文直接存为摘要是**正常行为**。
- 官网爬虫写 `sourceapi='官网抓取'`，固定 4 分，可能不经过摘要阶段 → 不纳入模型评分抽检和默认摘要缺失率。
- 公积金 `region` 无法可靠判断时可为空，不能把每个空值当错误。

### 统计定义（脚本实现）
| 指标 | 定义 |
|:----|:----|
| 新闻总数 | D 当天全部记录数（含官网） |
| 高分 | `score>=4` |
| NULL 评分 | 普通来源中 `score IS NULL` |
| 越界评分 | `score<0 OR score>5` |
| 摘要候选 | 普通来源（排除官网）且 `score>=3` 且 `TRIM(COALESCE(content,''))<>''` |
| 摘要缺失 | 候选里 `short_summary IS NULL OR TRIM(...)=''` |
| 评分均值 | 普通来源，`AVG(score)` 忽略 NULL（NULL 不计 0） |
| 空正文 | `content IS NULL OR content=''` |
| 纯空白正文 | `content<>'' 且 TRIM(content)=''` |

## 3. 数量判断
- 基线 = D 之前 7 天（不含 D）日均；有效天数写在 `baseline_valid_days`。
- 初始调查阈值：相对基线偏离 >40% **且** 绝对差 ≥10 条 → 「需关注」。这是减少小样本噪声的线索阈值，不是自动故障判据。
- 历史常有数据的主题突然归零 → 必须检查。
- 历史日期没有记录时，区分「零记录」与「未知原因缺失」，不悄悄当正常零产出，也不无声剔除。
- 有效样本 <3 天写「基线不足」；基线为 0 不计算百分比。
- 补查选项（最多一轮）：过去 4 个同星期对比（`weekday`）、按来源拆分（找消失/暴涨来源）、是否新主题/重复内容/题材变化。只做最能解释当前异常的一项。
- 当日无数据 → 报「尚未见到当日数据」，并核对检查时间，说明可能需人工查运行情况；不要直接断言定时任务没启动。

## 4. 抽检规则
- 每天默认 8 条普通来源；覆盖不同主题与高低分；其中 **≥4 条有摘要且正文 >500 字**（脚本 `constraints` 里核对）。
- 抽样用业务日期做随机种子（可复现）；禁止 `ORDER BY RAND()` 全表随机，禁止读整库正文。
- 分两步取：先元数据 → 再按 ID 批量取正文（`contents`）。
- 评分疑点：明显不相关内容拿高分、无正文/错误页/广告/模板被当高质量新闻。
- 摘要疑点：主体/事件/时间/金额/关键数字与正文矛盾、编造事实、混入其他新闻、输出报错或废话。
- 不算故障的：文风一般、轻微字数差异、短正文直接用原文当摘要。
- 追加定向核查上限 4 条；不得调用生产评分/摘要接口。
- 报告要写清实际检查条数、问题描述与记录 ID；随机样本与定向样本分开说；**小样本问题率 ≠ 全量错误率**。

## 5. 官网数据（只看库，不访问官网）
2026-09-19 用户确认：官网只检查**数据库里有没有烟草官网抓取记录**，有就有、没有就没有，不访问官网页面、不推断漏采。

- 查 `sourceapi='官网抓取'` 的**当日记录数**与**最近一个有产出的业务日期**，报告一句话：「官网：有，当日 N 条（id…）」或「官网：当日无抓取记录」。
- `keyword='中国烟草'` 的总量**不能**代替官网来源数量。
- 官网来源固定 4 分、无摘要可能（242 条历史记录里 28 条无摘要）、正文均值约 825 字 → 属正常，不纳入模型抽检与默认摘要缺失率。
- 量少（0–4 条/天、多天为 0）是常态，不告警、不联系上海机器、不猜测任务是否失败。
- **不要再访问官网列表页**：官网对本机反爬/不可达（`web_extract` 判内网地址、scrapling 测试记为 DNS 不可达），且用户已明确不需要网页核对。若将来要恢复网页核对，需用户明确要求并在能访问网络的机器上做。
- 库内长期边界：无日志 → 「执行日志未验证」，但不要每天当新故障反复告警。

## 6. 轻量纪律
- 正常：一轮聚合 ＋ 最多两轮抽样查询，不访问外部网页。
- 异常：最多追加约 3 次有明确目的的查询或少量网页核实。
- 总耗时默认 ≈5 分钟。
- 全量统计不靠心算；分项与总数必须对得上。

## 7. 共享/多机注意
- 库由多台采集机共享：新加坡跑主流水线，上海跑烟草官网任务。**不能从一条记录推断写入机器或任务完成时间。**
- 库中不存在入库时间字段，不要假定其存在。
